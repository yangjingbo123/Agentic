```bash

```

### 1.2 下载并准备数据

```bash
cd D:/科研/marl/agentic_rl
python data/prepare_data.py
```

脚本会自动下载 GSM8K 和 MATH（Level 3-5），转换为统一格式后保存到 `data/` 目录：

### 1.3 配置模型路径

编辑 `configs/default.yaml`，填入本地模型路径：

```yaml

```

## 第二阶段：冒烟测试（GSM8K，5道题）

目标：确认框架能跑通，loss 能反传，不报错。

### 2.1 运行

```bash
python train.py --stage agentic --config configs/default.yaml
```

### 2.2 正常输出示例

```
epoch=0 reward=0.250 acc=0.25 loss=0.0312 kl=0.0021 kl_coef=0.1000
epoch=0 reward=0.500 acc=0.50 loss=0.0287 kl=0.0019 kl_coef=0.1000
```

### 2.3 常见问题排查

| 现象 | 原因 | 解决方法 |
|------|------|----------|
| `CUDA out of memory` | 4个模型 + 4个 ref model 同时占显存 | 先注释掉 ref_models，只跑 2 个角色验证流程 |
| `loss=nan` | KL 爆炸或梯度爆炸 | 检查 `kl` 值；若 `kl > 10` 说明模型输出已崩溃，降低 `lr` |
| `KeyError: role_name` | messages 格式错误 | 检查 `agentic_executor.py` 的 `all_messages` 每条是否含 `role_name` 字段 |
| Qwen3 chat template 报错 | tokenizer 缺少 chat template | 在 `trainable_llm.py` 加载后检查 `tokenizer.chat_template` 是否为 None |
| `majority_vote` 返回空字符串 | Proposer 输出格式不符，解析失败 | 检查 `_parse_reasoning` 的正则是否匹配 Qwen3 的实际输出 |

## 第三阶段：正式训练

### 3.1 切换到 MATH 数据集

修改 `configs/default.yaml`：

```yaml
data:
  train_path: "data/math_train.jsonl"
  test_path:  "data/math_test.jsonl"

agentic:
  epochs: 3
  n_samples: 4
  lr: 1.0e-5
  clip_epsilon: 0.02
  max_tokens: 512
  max_interactions: 3
  kl_coef: 0.1
  target_kl: 6.0
  max_grad_norm: 1.0
```

### 3.2 启动训练

```bash
python train.py --stage agentic --config configs/default.yaml
```

训练完成后，各角色的 LoRA 权重保存在：

```
checkpoints/
├── controller/
├── proposer/
├── critic/
└── verifier/
```

## 第四阶段：评估

### 4.1 三个 Benchmark 的评估顺序

| 顺序 | Benchmark | 用途 | 预期指标 |
|------|-----------|------|----------|
| 1 | GSM8K test | 验证框架基本可行性 | Accuracy |
| 2 | MATH Level 3-5 test | 主实验核心指标 | Accuracy |
| 3 | AIME 2024/2025 | 挑战性评测，与 ReMA 对比 | Accuracy |

### 4.2 对比实验组

| 方法 | 说明 | 验证什么 |
|------|------|----------|
| Baseline | 固定流程 P→C→V，LLM 不训练 | 不训练的上限 |
| 无交互 Agentic RL | 去掉 `<interaction>`，只用 GRPO 训练 | 训练本身的贡献 |
| 无 Controller | 去掉高层，低层固定轮数 | Controller 的贡献 |
| **完整框架（本方法）** | 分层 MARL + 交互可学习 + GRPO | 完整方法 |

### 4.3 公平性控制

所有方法统一：
- 基础模型：相同的 Qwen3-7B checkpoint
- 每个 turn 最大 512 tokens
- 评估时使用 greedy decoding，不做多采样投票
- Baseline 的 token budget 与本方法 `budget=standard` 对齐

## 第五阶段：训练监控

### 5.1 关键指标含义

| 指标 | 含义 | 健康范围 |
|------|------|----------|
| `mean_reward` | 组内平均总奖励（含中间奖励） | 随训练缓慢上升 |
| `accuracy` | 组内答对比例 | 随训练上升 |
| `loss` | GRPO-Turn loss | 波动正常，不应持续上升 |
| `kl` | 当前策略与 ref model 的 KL 散度 | 应在 target_kl=6.0 附近 |
| `kl_coef` | AdaptiveKLController 自动调整的系数 | 若持续增大说明 KL 失控 |

### 5.2 训练不稳定的信号

- `kl > 20`：策略偏离过大，考虑降低 `lr` 或增大 `kl_coef`
- `loss` 持续为 0：梯度没有反传，检查 `requires_grad` 设置
- `accuracy` 长期为 0：Proposer 输出格式解析失败，检查 prompt 和正则

## 附：超参数参考

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `n_samples` | 4 | GRPO 组内采样数，越大越稳定但越慢 |
| `clip_epsilon` | 0.02 | Turn-level PPO clip，比 token-level 更小 |
| `lr` | 1e-5 | LoRA 学习率 |
| `max_interactions` | 3 | 每个 round 最多触发交互次数 |
| `kl_coef` | 0.1 | KL 惩罚初始系数 |
| `target_kl` | 6.0 | AdaptiveKL 的目标 KL 值 |
| `max_grad_norm` | 1.0 | 梯度裁剪阈值 |
